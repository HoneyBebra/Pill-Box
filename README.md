# Pill-Box
Приложение напоминаний о приёмах лекарств, также ведёт учёт
количества оставшихся лекарств в аптечке

---

## Схема базы данных

Схема описывает таблицы для учёта запасов лекарств, расписания приёма и уведомлений. Пользователи берутся из стандартной модели Django `auth_user`.

### Диаграмма связей

### Таблицы

#### 1. `medicine` — запасы в домашней аптечке

| Поле        | Тип           | Описание                                      |
|-------------|---------------|-----------------------------------------------|
| id          | PK            | Первичный ключ                                |
| user_id     | FK → auth_user| Владелец записи                               |
| name        | VARCHAR       | Наименование лекарства                        |
| quantity    | INT/DECIMAL   | Количество оставшихся единиц (таблеток и т.п.) |
| unit        | VARCHAR       | Единица учёта (таблетки, капсулы, мл и т.д.)  |
| description | TEXT          | Описание / заметки о лекарстве                |
| created_at  | DATETIME      | Дата создания                                 |
| updated_at  | DATETIME      | Дата обновления                               |

- Один пользователь может иметь много записей о лекарствах.
- По `medicine` строится расписание и списание остатков.

---

#### 2. `schedule` — расписание приёма лекарств

| Поле         | Тип            | Описание                                                                                                        |
|--------------|----------------|-----------------------------------------------------------------------------------------------------------------|
| id           | PK             | Первичный ключ                                                                                                  |
| user_id      | FK → auth_user | Владелец расписания                                                                                             |
| medicine_id  | FK → medicine  | Какое лекарство принимать                                                                                       |
| time         | TIME           | Время приёма (например, 08:00, 20:00)                                                                           |
| days_bitmask | JSON   | Сумма степеней двойки по дням (пн=1, вт=2, ср=4, ..., вс=64). Таким образом расписание, например, пн-вт-чт = 11 |
| dosage_amount | DECIMAL        | Сколько единиц за один приём (1 таблетка, 2 капсулы)                                                            |
| is_active    | BOOLEAN        | Включено ли напоминание                                                                                         |
| created_at   | DATETIME       | Дата создания                                                                                                   |
| updated_at   | DATETIME       | Дата обновления                                                                                                 |

- Одно лекарство может входить в несколько записей расписания (например, утро и вечер).
- По этой таблице формируются напоминания (уведомления).

---

#### 3. `active_tasks` — запланированные напоминания (можно отменить по task_id)

| Поле         | Тип            | Описание                                                                |
|--------------|----------------|-------------------------------------------------------------------------|
| id           | PK             | Первичный ключ                                                          |
| user_id      | FK → auth_user | Пользователь                                                            |
| schedule_id  | FK → schedule  | Правило расписания                                                      |
| scheduled_at | DATETIME       | Момент приёма (дата + время), на который поставлена задача в очередь    |
| task_id      | VARCHAR        | ID задачи в очереди (напр. Celery) — для revoke при удалении расписания |
| status       | VARCHAR        | Состояние: `pending` / `sent` / `cancelled`                             |

- При постановке задачи в очередь создаётся запись со `status=pending`, сохраняется `task_id`.
- При удалении или деактивации приёма в расписании: для записей с этим `schedule_id`, `status=pending` и `scheduled_at` в будущем вызывается revoke по `task_id`, затем `status=cancelled`.

---

#### 4. `notification_log` — лог отправленных напоминаний

| Поле         | Тип             | Описание                                  |
|--------------|-----------------|-------------------------------------------|
| id           | PK              | Первичный ключ                            |
| user_id      | FK → auth_user  | Кому отправлено                           |
| schedule_id  | FK → schedule   | По какому правилу расписания              |
| scheduled_at | DATETIME        | Когда был запланирован приём              |
| sent_at      | DATETIME        | Когда отправлено уведомление              |
| channel      | VARCHAR         | Канал (email, push, sms и т.д.)           |

- Нужна для истории и повторной отправки: не слать одно и то же напоминание дважды.
